## 1. 动机

### 1.1 现状

PWA 信息（`manifest.webmanifest` 的 `name` / `short_name` / `description` 与 9 个 HTML 入口的 `<meta name="apple-mobile-web-app-title">`）**硬编码中文**，未纳入 i18n：

- `web/public/manifest.webmanifest` 全部字段中文；Vite `public/` 原样拷贝到 `web/dist/`。
- 9 个 `web/*.html` 的 `apple-mobile-web-app-title` 均为 `content="小记"`。
- Phase 3（[ADR 20260806-phase3](20260806-phase3-web-i18n-onboarding.md)）在 `docs/i18n/i18n.md:167` 提到的「PWA / shadcn 兼容」仅是技术栈兼容性声明，未把 PWA 字符串实际纳入字典；Phase 3 改动清单也未列 manifest / apple-mobile-web-app-title。

### 1.2 问题

英文界面用户安装 PWA 后，主屏图标名称、应用标题、安装提示中的应用名仍为中文「小记」，与界面语言不一致。

### 1.3 架构约束

PWA manifest 在 **pre-auth** 阶段就要可达：

- [ws-router.md:138,174,181](../impl-spec/multiple-users/ws-router.md) 明确 `/manifest.webmanifest` 在 `STATIC_WHITELIST_PREFIXES` 中，绕过认证 —— iOS Safari 在登录页就能触发「添加到主屏」，必须能读到 manifest。
- 因此 manifest 端点在多用户部署下**无法读取 user profile**（ws-router 不持有各 ws-container 的 yaml），只能依赖请求自带的语言信号（`Accept-Language`）。
- web_acceptor（单机部署 / ws-container 内）可读 `load_profile()`，可做 profile 优先 + Accept-Language 兜底。

## 2. 决策

| # | 决策点 | 选择 |
|---|---|---|
| 1 | manifest 协商方式 | 动态端点 + `Vary: Accept-Language`（不再纯静态 `FileResponse`） |
| 2 | apple-mobile-web-app-title 注入 | 服务端按 Accept-Language 在 HTML 入口注入（占位符 `{{pwa_short_name}}` 替换） |
| 3 | post-auth 优先级 | web_acceptor：profile 优先，Accept-Language 兜底；ws_router：仅 Accept-Language（架构限制，见 §3.2） |
| 4 | 范围 | 仅 web PWA manifest（不动 Chrome Extension MV3 `manifest.json`，继续按 Phase 4 既定决策不引入 `chrome.i18n`） |
| 5 | PWA 文案真源 | 后端 Python dict（`src/everlingo/i18n/pwa.py`，与 `messages.py` 同模式），前端 `web/src/locales/` 不动 |
| 6 | `short_name` 与前端 `app_name` | 独立定义（不复用前端 `chatbot.json` 的 `app_name`，避免跨层耦合） |

## 3. 设计要点

### 3.1 文案真源：`src/everlingo/i18n/pwa.py`

新建 `src/everlingo/i18n/pwa.py`（与 Phase 2 的 `messages.py` 同目录同模式）：

```python
PWA_MANIFEST_TEXT: dict[str, dict[str, str]] = {
    "zh-CN": {"name": "...", "short_name": "...", "description": "..."},
    "en":    {"name": "...", "short_name": "...", "description": "..."},
}
```

manifest 端点直接 `import` 使用；不读前端 JSON 字典，避免后端运行时多一次文件 I/O 与跨层耦合。

### 3.2 语言协商：`resolve_manifest_language()`

新增 `resolve_manifest_language(accept_language, interface_language=None) -> str`，优先级：

1. `interface_language` 非空且 ∈ `AVAILABLE_INTERFACE_LANGUAGES` → 直接用（仅 web_acceptor 传，ws_router 不传）
2. `parse_accept_language(accept_language)` 解析 q-value 列表，首个命中 `AVAILABLE_INTERFACE_LANGUAGES`（精确或前缀 `zh*`→`zh-CN`、`en*`→`en`）→ 返回
3. 兜底 `"en"`

`parse_accept_language()` 复用 `resolve_interface_language()`（`models.py:230`）的归一化逻辑（提取为内部 helper `_normalize_lang_tag()`，主函数行为不变，向后兼容）。

**ws_router 不传 `interface_language`**：多用户部署下 ws_router 不持有各 ws-container 的 profile yaml，manifest 端点 pre-auth 白名单绕过认证也拿不到 `request.state.user_id`。这是可接受的折中：用户登录后浏览器仍带 Accept-Language，manifest 与浏览器语言一致；与用户在 onboarding 选的界面语言可能不同，但能工作，且 manifest 语言一旦在安装时确定后浏览器会缓存（`Cache-Control: no-cache` 仍允许协商，但用户不会频繁重装）。

### 3.3 manifest 端点：动态响应

`web/public/manifest.webmanifest` 仅保留语言无关字段（`start_url` / `scope` / `display` / `orientation` / `background_color` / `theme_color` / `icons`），删除 `name` / `short_name` / `description`（运行时由后端注入）。

服务端 `_serve_manifest(request)`：
1. 读 `request.headers.get("Accept-Language")`；
2. 调 `resolve_manifest_language(...)`（web_acceptor 额外传 `load_profile().language.interface_language`）；
3. 从 `web/dist/manifest.webmanifest` 读语言无关字段（或硬编码模板），合并 `PWA_MANIFEST_TEXT[lang]` 的三个字段，`json.dumps`；
4. 返回 `Response(content=json, media_type="application/manifest+json", headers={"Cache-Control": "no-cache", "Vary": "Accept-Language"})`。

### 3.4 HTML 入口占位符替换

9 个 `web/*.html` 的 `<meta name="apple-mobile-web-app-title" content="小记">` 改为 `content="{{pwa_short_name}}"`。Vite 构建不处理 meta content，占位符原样保留到 `web/dist/*.html`。

服务端 `_serve_html_with_i18n(file_path, request, cache=HTML_CACHE_CONTROL)`：
1. 读 HTML 文件内容为字符串；
2. 按 `resolve_manifest_language(...)` 取 `PWA_MANIFEST_TEXT[lang]["short_name"]`；
3. `html.replace("{{pwa_short_name}}", short_name)`；
4. 返回 `Response(content=html, media_type="text/html", headers={"Cache-Control": cache, "Vary": "Accept-Language"})`。

不引入 Jinja2 / 模板引擎（保持轻量；只有一处占位符，字符串替换足够）。其余 meta（`theme-color`、`manifest` link、`apple-touch-icon`、`apple-mobile-web-app-capable`）语言无关，不动。

### 3.5 缓存头

| 资源 | Cache-Control | Vary |
|---|---|---|
| `/manifest.webmanifest` | `no-cache`（保留 ADR 20260804） | **新增 `Accept-Language`** |
| HTML 入口（9 个） | `no-store, must-revalidate`（保留） | **新增 `Accept-Language`**（apple-mobile-web-app-title 随语言变） |
| `/assets/**`、`/icon-*.png`、`/favicon.png` | immutable / no-store（不变） | 无 |

### 3.6 改动点分布

| 文件 | 改动 |
|---|---|
| `src/everlingo/i18n/pwa.py` | **新建**：`PWA_MANIFEST_TEXT` + `parse_accept_language` + `resolve_manifest_language` |
| `src/everlingo/models.py` | `resolve_interface_language()` 提取 `_normalize_lang_tag()` helper（行为不变，向后兼容） |
| `src/everlingo/ws_router/app.py` | manifest 分支改 `_serve_manifest(request)`；HTML 入口（`/login`、`/self-service`、`/self-service/pat`）改 `_serve_html_with_i18n()` |
| `src/everlingo/gateway/web_acceptor.py` | manifest 端点改 `_serve_manifest(request)`（传 profile）；HTML 入口（`/editor`、`/console/me`、`/console/me/target-language`、`/console/me/interface-language`、`/console/web-console`、`/` catch-all）改 `_serve_html_with_i18n()` |
| `web/public/manifest.webmanifest` | 删 `name` / `short_name` / `description` 三字段 |
| `web/*.html`（9 个） | `apple-mobile-web-app-title` content 改 `{{pwa_short_name}}` |

### 3.7 测试

- `tests/test_i18n_pwa.py`：`parse_accept_language` 各情形、`resolve_manifest_language` 优先级、web_acceptor manifest 端点（profile 优先 / Accept-Language 兜底 / Vary 头）、HTML 占位符替换。
- ws_router manifest 测试：不同 Accept-Language 返回不同 name、`Vary: Accept-Language` + `Cache-Control: no-cache`。

## 4. 不在本 ADR 范围

- **Chrome Extension MV3 `manifest.json`**：继续按 [i18n.md Phase 4](../i18n/i18n.md) 既定决策「不引入 `chrome.i18n` / `_locales/`」。Extension 的 `manifest.json` 的 `name` / `description` 维持现状。
- **Service Worker / 离线能力**：仍不引入（[ADR 20260804 §5](20260804-web-cache-control.md)）。
- **manifest 语言写回用户配置**：用户在浏览器选了 en 但 profile 是 zh-CN，不会反向更新 profile。manifest 语言仅为运行时协商结果。
- **多份静态 manifest + hreflang**：本 ADR 选动态端点，不产出 `manifest.zh-CN.webmanifest` / `manifest.en.webmanifest` 多份静态文件。
- **`theme_color` / `icons` 随语言变化**：当前 `theme_color` / `icons` 语言无关；如未来需要按语言出不同图标，再扩展。

## 5. 替代方案考虑

| 方案 | 否决理由 |
|---|---|
| 多份静态 manifest + JS 运行时改 `<link rel="manifest" href>` | iOS Safari 在用户触发「添加到主屏」瞬间读取 `<link rel="manifest" href>` 的时机与 JS 执行时序不可靠；若 JS 未跑完或被 ErrorBoundary 拦截，读到的是默认 href 的 manifest，语言可能错 |
| 多份静态 manifest + 服务端 HTML 注入 `<link rel="manifest" href>` | 需把 9 个 HTML 入口从静态文件改为模板渲染（注入 href），与 apple-mobile-web-app-title 注入同路径但更复杂；动态端点 + Vary 更简单 |
| JS 运行时改 `<meta name="apple-mobile-web-app-title">` content | iOS Safari 在用户触发「添加到主屏」时读 HTML 原始 meta 的时机不可靠，可能读到中文「小记」 |
| manifest 文案真源放前端 `web/src/locales/{zh-CN,en}/pwa.json` | 后端 manifest 端点要多一次文件 I/O 读前端 JSON；跨层耦合；与 Phase 2 后端文案真源（`src/everlingo/i18n/messages.py`）模式不一致 |
| `short_name` 复用前端 `chatbot.json` 的 `app_name` | 跨层耦合（后端读前端 JSON 或构建时同步）；manifest 的 short_name 语义可能未来与 chatbot 标题分化（如 short_name 受 12 字符限制，app_name 不受） |
| ws_router 登录后转发 manifest 请求到 ws-container 协商 | 与 ws-router.md:181「manifest pre-auth 本地服务」决策矛盾；增加 ws_router 代码复杂度；登录前/后行为不一致 |
| 始终用 Accept-Language（web_acceptor 也不查 profile） | 与 i18n Phase 3「最终以服务端 resolved 为准」语义不一致；用户在 onboarding 选 en 但浏览器 zh → manifest 仍中文 |

## 6. 实施顺序

1. **后端 i18n 基建**：新建 `src/everlingo/i18n/pwa.py`（`PWA_MANIFEST_TEXT` + `parse_accept_language` + `resolve_manifest_language`）；`models.py` 提取 `_normalize_lang_tag()` helper；纯函数单测。
2. **后端端点改造**：`web_acceptor.py` 与 `ws_router/app.py` 各自新增 `_serve_manifest(request)` + `_serve_html_with_i18n()`，替换原静态 FileResponse 调用点；端点集成测试。
3. **前端占位符**：`web/public/manifest.webmanifest` 删三字段；9 个 `web/*.html` 改 `{{pwa_short_name}}`。
4. **集成测试**：`tests/test_i18n_pwa.py` + ws_router manifest 测试。
5. **文档**：本 ADR + `docs/i18n/i18n.md` Phase 5 + `web-chatbot.md` §PWA + `ws-router.md` + `web-session-acceptor.md` + `TASKS.md` + release notes。

每步跑相关单测（`uv run pytest tests/test_i18n_pwa.py -v`），无需全量。
