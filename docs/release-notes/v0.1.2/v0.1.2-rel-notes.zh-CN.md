# 🎉 EverLingo v0.1.2 release notes

## 新功能

- 支持笔记自动同步到你指定的任意 github 等 git 仓库上
- 支持聊天中分析任意图片，如题目照片、手机截图等等。并自动嵌入图片到笔记
- 支持笔记图片。包括 Web / 微信端
- 支持 i18n 英语界面和聊天
- WS-Master 新增对环境变量的透传支持：进程 env 中凡以 `WS_CONTAINER_` 前缀开头的变量，去前缀后作为 ws-container 的环境变量注入（透传优先于显式 env）。典型场景——在 compose 的 `ws_master` service 设置 `WS_CONTAINER_HTTP_PROXY` / `WS_CONTAINER_HTTPS_PROXY` / `WS_CONTAINER_NO_PROXY`，即可让 ws-container 出网走企业代理访问 OpenAI / OpenRouter API，而无需改镜像。

## 功能增强

- `reset_vault` 覆盖模板 spec 前先把当前改动快照进 git 历史，用户对 spec 的修改不再被静默丢失。
- `user_doc_set` 不再写 `USER.md.bak`：历史改由 Memory Vault 的 git 版本控制统一回溯。

## 内部调整

- 新增 `src/everlingo/mem/vault/version/` 包：`git.py`（subprocess 封装 git CLI：init/status/commit/push/fetch/rebase/log/branch/reset，统一带 `-c safe.directory` 规避挂载 workspace 的 UID 不匹配）、`committer.py`（定时器 commit 去抖 + push 间隔，initial commit 兜底与 atexit/stop final commit）、`ssh_key.py`（临时私钥生命周期 + `GIT_SSH_COMMAND` 注入，含 `StrictHostKeyChecking=accept-new`）、`restore.py`（commit → fetch → rebase，冲突归档到 `backup/restore-<ts>` 分支且不覆盖工作区）。
- `everlingo.yaml` 新增 `git_backup` 配置段（`enabled` / `remote_url` / `branch` / `auth` / `commit_interval` / `push_interval`），提供 `setting.load_git_backup()` / `save_git_backup()`。
- indexer `AppState` 持有 `Committer`，随进程 lifespan 启停；首次启动懒加载 `git init` 并做 initial commit 捕获存量 vault 内容。
- indexer HTTP 新增 `/version/status`、`/version/commit`、`/version/push`、`/version/pull`、`/version/log`、`/version/restore` 端点，SearchClient 补充对应方法。
- indexer 启动时强制将本地 git 分支重命名为配置的 `branch`（`git branch -M`）：异机初始化或手工拿到的 Memory Vault repo，无论原分支名是什么，push / fetch-rebase / status 的判断都保持一致。


- 新增备份配置页 `/console/me/backup`（Me 页常驻入口）：展示仓库状态（初始化 / dirty / 上次提交 / ahead-behind / 远端 / 分支）、配置表单（开关 / 远端 URL / 分支 / SSH 私钥）、操作区（测试连接 / 立即快照 / 立即推送 / 拉取恢复 / Hard Reset 二次确认）与提交历史列表。
- 新增 gateway REST API `/api/backup/*`（status/config/snapshot/push/pull/test/reset-hard/log/restore），复用 indexer 的 `/version/*` 端点经 UDS 委托，配置读写 `everlingo.yaml` 的 `git_backup` 段。


- 新增「强制推送」操作，执行 `git push --force`（无条件覆盖远端历史，UI 带二次确认）：新增 `/version/force-push`、`/api/backup/force-push` 端点，备份页「立即推送」右侧新增「强制推送」按钮，以及 `everlingo mem force-push` CLI 命令。


- 配置保存即热生效：新增 `/version/apply-config` 端点 + `Committer.apply_config()/reload_config()`，保存配置后自动启停 committer 定时线程、重配 SSH 上下文，无需重启 indexer 进程。
- 新增「测试连接」：`git ls-remote` 只读探测配置的远端（复用 `git_backup` 凭证），接入 `/version/test` 端点。
- 新增「Hard Reset 到远端」强操作：`/version/reset-hard` 直接 `git reset --hard origin/<branch>`，UI 带二次确认（`git_backup` 配置后由用户显式触发，冲突恢复场景的兜底分支逻辑沿用 `restore.py`）。

- Web 聊天机器人现支持上传图片（文件选择 / 粘贴截图 / 拍照）并随消息一起发送：图片在后端落盘，消息 envelope 通过 `chat.attachments[].src_resource_sha256` 引用，上传的图片立即渲染在用户气泡中。
- 新增 `PUT /api/session/{session_id}/images/{src_resource_sha256}`（multipart）：校验 MIME（jpeg/png/webp）与 SHA-256，存储到 `{workspace}/sessions/{session_id}/images/{sha256}.{ext}`，返回 `ImageAsset` 元数据；同一图片重复上传幂等。
- 新增 `ImageStore` 抽象层（`src/everlingo/image/`），后端后续可把本地文件系统存储替换为真实对象存储而无需改动调用方；MVP 阶段消息端点限制每条消息最多 1 张图片。


- envelope 模式扩展 `chat.attachments[]`（`src_resource_sha256` + `type`），Python 端（`AttachmentPart` / `ChatPart.attachments`）与 TypeScript 端同步；Chat Agent 暂不消费 attachments（二期/三期将加入 Vision 分析工具）。


- 新增 Vision Service 层（`OpenRouterVisionService`）：读取已存储的图片字节，调用支持视觉的 OpenRouter 模型（默认 `xiaomi/mimo-v2.5`，可配置）输出结构化 `ImageAnalysis`（OCR `text` + 业务层的 `structured_content` + `knowledge_points`）。遵循 ADR 原则：Vision 只回答「图片里有什么」，绝不输出答案/解析。
- Vision 结果按 `src_resource_sha256 + model + prompt 版本` 做进程内 LRU + 7 天 TTL 缓存，全局（跨用户）共享——热门学习图片（如常见英语题）至多分析一次；并发防护保证同一图片的并发分析合并为一次 Vision Model 调用。
- 图片上传后在后台异步预热 Vision 缓存（fire-and-forget、不阻塞、失败静默），Agent 工具多数情况直接命中缓存，首响延迟更低。


- 上传图片在保存时用 Pillow 预处理：先 EXIF 方向校正、再剥离元数据、超 1920x1200 按比例缩放；`saved_resource_sha256` 按处理后的字节重算，并填充 `width/height`。新增依赖：`pillow`。
- 新增 `VisionPurpose`（ocr / exercise / document / learning_content / general）与 `ImageInput` 引用模型；`ImageAnalysis.structured_content` 刻意用宽松 dict 以容纳随内容类型变化的形态。
- 新增 `analyze_image` 工具（`make_vision_tool`），在支持图片的通道（web）注册：Agent 用 envelope 里的 `src_resource_sha256` 调用，拿到 `ImageAnalysis` 作为工具消息。Vision 失败时工具返回友好降级文案而不是抛异常（ADR 错误码 `VISION_MODEL_UNAVAILABLE` / `VISION_ANALYSIS_FAILED` / `VISION_OUTPUT_INVALID`）。
- 新增 `get_vision_llm_config()` / `vision_model` 配置（`setting.sys_setting.vision_model` / env `VISION_MODEL`，默认 `xiaomi/mimo-v2.5`）与 `create_vision_llm()`（temperature 0，超时 120s）；`ChannelMetadata` 增加 `supported_image`（web 通道置位）。


- 把已实现的 Image Store 与 Vision Service 设计从 ADR 沉淀为正式 Implementation Spec：新增 `docs/impl-spec/vision/image-store-spec.md`（数据模型、存储布局、前端 `PUT /api/session/{session_id}/images/{src_sha}` 上传端点契约、Pillow 预处理、错误映射、生命周期）与 `docs/impl-spec/vision/vision-service-spec.md`（感知边界、`ImageAnalysis`、缓存/并发防护、Eager Warm + 工具取用混合模式、`analyze_image` 工具接入、错误码）。


- Vault Editor 后端支持在 markdown 笔记中插入图片：`image_store.py` 新增 `save_vault_image()`，把图片字节写入语言 vault 内相对路径（复用 EXIF 校正 / 元数据剥离 / 超限缩放预处理），校验文件名 stem 为合法 SHA-256 并作为 `src_resource_sha256`（信任语义——前端可能上传缩放后的字节，不再重算比对），best-effort 追加自有溯源元数据（JPEG EXIF UserComment / PNG tEXt `src_resource_sha256=...`），并按路径幂等。
- 新增 `GET`/`PUT /api/vault/raw/{lang}/{vault_rel_path:path}`：PUT 上传 multipart `file` 字段（MIME 允许列表 415；空文件 / stem 非法 sha / 路径逃逸 / 图片不可解析 400；重复上传幂等）并返回 `ImageAsset` 元数据；GET 服务 vault 内任意文件，按扩展名定 Content-Type（图片 inline、文本类 text/plain、其它 octet-stream）并带 immutable 缓存头。两端点与既有 `read` 端点相同的信任边界（resolve + `is_relative_to(vault_root)`）。


- `docs/impl-spec/vision/image-store-spec.md` 新增「Vault 图片存储」小节，描述 `save_vault_image`（校验、预处理 + 自有元数据、按路径幂等、`memory://languages/{lang}/vault/...` storage_key）。


- Vault Editor 编辑区 sub-header 新增「插入图片」按钮（图标 + 文字，移动端仅图标）：选择文件（移动端由系统提供「拍照 / 从相册选择」选项——**不使用** `capture` 属性，iOS 下 `capture` 会强制只打开相机、隐藏相册），图片上传到 vault 内默认的 `<md目录>/<md名>.assets/` 目录，并在光标处插入标准 markdown 图片语法。
- 编辑区还支持**粘贴图片**（Ctrl/Cmd+V）：从剪贴板取出图片（仅 JPEG/PNG/WebP），走与按钮完全相同的上传+插入流程；纯文本粘贴不拦截。剪贴板同时含图片与文本时按图片处理。
- markdown 内保存**相对路径**图片链接（可移植、与 `lang` 解耦、搬文件也不影响），WYSIWYG 预览时改写为绝对 `/api/vault/raw/{lang}/{path}` URL、保存前逆改写回相对路径（`imageLinks.ts` 的 `toDisplay`/`toRelative`）。
- 前端先对**原始字节**计算 SHA-256，再在 canvas 中按需缩放到 ≤1920×1200（`imageScale.ts`），以原始 sha 命名上传；缩放失败回退原图（后端预处理仍保证尺寸上限）。


- 新增 `web/src/editor/services/imageLinks.ts`（相对↔绝对链接改写 + vault 路径工具）、`imageScale.ts`（按需 canvas 缩放）与 `pasteImage.ts`（`extractImageFile` 剪贴板取图）；`vaultApi.ts` 新增 `uploadImage`/`assetUrl`，`types/vault.ts` 新增 `ImageAsset`。
- `MilkdownEditor`/`SourceEditor` 经 `insertImageRef` 暴露光标插入（WYSIWYG 插入 src 为绝对 URL 的 image 节点，Source 模式插入相对 markdown 文本）；`EditorApp` 在编辑区以 capture 阶段监听 `paste` 复用同一流程。
- 新增 i18n 文案 `insert_image` / `insert_image_uploading` / `insert_image_failed` / `insert_image_save_first`（zh-CN / en）。


- 修订 ADR `docs/ADR/20260816-markdown-image.md`：决策 4/5 改为信任路径 stem 为前端 scale 前 SHA（仅格式校验、不重算比对）、错误表 `sha256 mismatch` 语义、默认上传路径规则（`{md_dir}/{mdname}.assets/...`）、Phase 2 执行计划（前端缩放 + 后端契约微调）。
- 完成 ADR Phase 3 文档回填：`docs/impl-spec/vault-editor.md` 新增「图片插入」节（按钮/accept/capture、`currentPath` 前置校验、默认上传路径规则、scale 前 SHA、WYSIWYG 绝对 / Source 相对插入形态、`toDisplay`/`toRelative` 改写规则与已知限制、上传状态）并删除「不在本 spec 范围」图片行；REST 端点表补 `PUT/GET /api/vault/raw/{lang}/{vault_rel_path}` 两行（进程内直调、不经 MCP）；`vault-mcp-spec-tools.yaml` 核对共 18 个工具并加注说明（图片上传/取回不经 MCP，无需新增工具）；`image-store-spec.md` 交叉引用改指已完成的 vault-editor.md。ADR 状态置为 Accepted，Phase 3 各步骤标 ✅。


- 聊天图片现在可以写入笔记：新笔记流程的 Memory Writer 与编辑流程的 Chat Agent 都能通过新增的 `copy_session_image_to_vault` 工具，把 session 图片复制到 vault——工具读取已存储的图片字节，写到 `<md目录>/<md名>.assets/` 下可读命名的 `{slug}-{src_sha前8位}.{ext}` 文件，并返回 markdown 相对路径，笔记正文即可用 `![alt](...)` 引用（LLM 不做路径算术）。
- slug 来自 Agent 从 `analyze_image` 结果提炼的简短英文提示（如 `english-exercise`），由代码端 `slugify()` 归一化；`-{src_sha前8位}` 后缀保证唯一与按路径幂等，完整 `src_resource_sha256` 仍写入 JPEG EXIF / PNG tEXt 溯源元数据。
- `save_vault_image()` 新增可选 kwarg `src_resource_sha256`：省略时保留旧行为（从 stem 提取 + 64-hex 校验，前端编辑器上传契约不变）；显式传入时 stem 可为英文 slug（对传入值本身做 64-hex 校验），使 Agent 流程可复用同一套预处理与幂等写盘。

- Wechat 通道现支持接收图片并进行 LLM 分析：收到带图片的微信消息时，服务端下载原始字节、嗅探 MIME（jpeg/png/webp）、计算 SHA-256，复用与 Web 相同的 `image_store.save` 落盘链路，并随消息 envelope 携带 `chat.attachments[].src_resource_sha256`。
- 开启 Wechat 通道的 `supported_image`：Agent 自动注入 `analyze_image` / `copy_session_image_to_vault` 工具，微信图片既能被 Vision 分析讲解，也能沉淀到笔记（与 Web 通道能力对齐）。
- 图片上传后同样在后台异步预热 Vision 缓存（fire-and-forget），与 Agent 工具调用共用缓存与并发防护；多图消息只取第一张（对齐单图限制），下载失败/格式不支持时「有文字则丢图保留文字，纯图则回友好提示」。

- 新增 ADR `docs/ADR/20260818-image-chat-wechat.md` 记录设计决策（服务端复刻 web 流程、统一 Session loop、src_sha=下载原始字节 SHA、MIME 嗅探、失败/多图降级、`eager_warm` 共享、`supported_image` 门控）。
