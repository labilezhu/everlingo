# 🎉 EverLingo v0.1.1 release notes

## 新功能

- 目标学习语言设置页添加「重新初始化」按钮：用户可一键重置知识库规范（spec/）到模板初始状态，覆盖用户自定义修改。

## 功能增强

- 界面语言 `interface_language` 由必选改为可选：未配置时运行时按操作系统语言（OS locale）自动推断，命中不到时兜底英文 `en`；界面语言与目标学习语言解耦为两个独立集合（当前可用界面语言 `zh-CN`/`en`）。推断值不写入配置文件，后续由首次引导让用户显式选择。
- 后端用户可见兜底文案国际化：AI 出错 / 服务不可用等兜底回复按界面语言（中文/英文）返回，英文界面下不再收到中文错误提示。
- Me 页底部展示当前 EverLingo 版本号，便于用户识别运行版本。
- 首次使用引导新增第一步「选择界面语言」：首次运行强制跳转设置界面语言页，用户显式确认后写入配置并进入下一步；Me 页新增「界面语言」入口，可随时切换，切换即时生效（无需刷新），并由后端触发 Agent 重建。
- Web 前端界面全面国际化：Chatbot、笔记编辑器、Web Console、登录/自服务/PAT 等页面文案改为中英双语字典驱动，随界面语言自动切换。
- Web Chatbot 会话状态持久化：chatbot 与笔记编辑器之间跳转（整页刷新）后，同一浏览器 Tab 内保持同一会话与消息历史，AI 上下文连续，不再清空。
- 会话按 Tab 隔离：新开 Tab 得到独立新会话，用户可在浏览器中同时保留多个互不干扰的对话。
- 文件树中根层 `spec/` 与 `events/` 目录默认收起，减少视觉干扰，用户可手动展开。
- PWA 安装信息（manifest 的应用名/短名/描述 与 iOS 添加到主屏标题）按请求语言动态协商：英文界面用户安装 PWA 后应用名显示英文，中文界面显示中文。
- Chrome Extension（sidecar 面板与设置页）界面文案国际化：随后端返回的用户界面语言（zh-CN/en）自动切换，右键菜单「翻译」文案亦随之本地化。
- 建立新语言知识库（Vault）的初始化模板按界面语言本地化：`create_vault` / `reset_vault` / `session.configure` 创建的 `spec/` 规范、`items/` 与 `events/` 目录标题随用户界面语言（中文/英文）生成，英文界面用户不再得到中文规范说明。
- 记忆库事件文件（events/）首次创建时的前置内容按界面语言本地化：英文界面不再出现中文「当天事件」标题；「为什么记住」字段 `why_want_to_save_memory` 改为由 AI 按界面语言自由撰写一句原因（非固定中文枚举）。

## 内部调整

- 前端引入 i18n 框架（react-i18next + i18next）：新增 `web/src/i18n/`（多入口 bootstrap：先按浏览器语言启发式渲染首屏，再以服务端 `interface_language_resolved` 校正，/login 跳过状态请求防 401 死循环）与 `web/src/locales/{zh-CN,en}/` 九类字典；全部 9 个 Vite 入口接入统一 bootstrap。
- 前端引入 vitest + @testing-library 测试栈：覆盖 i18n 字典一致性（zh/en key 深度相等、占位符一致）、bootstrap 顺序、detect 启发式、界面语言页交互，共 17 用例。
- 新增 `GET /api/user-profile/status` 接口语言字段（`interface_language` / `interface_language_resolved` / `available_interface_languages`）与 `POST /api/user-profile/interface-language` 写入端点（校验 + 写 yaml + 显式 `bump_prompt_version()` 触发 Agent 重建），并为 `/console/me/interface-language` 静态页 fallback。

- 所有 LLM 请求统一携带应用标识 headers（`User-Agent: EverLingo/<版本号>`、`HTTP-Referer`、`X-Title`），便于在 OpenRouter 等平台上识别 EverLingo 流量来源；版本号统一收敛到 `src/everlingo/__init__.py` 的 `__version__`，并纳入 release 流程自动替换。

- 新增 `src/everlingo/i18n/` 消息字典与取值函数 `t(key, interface_language)`：后端兜底文案集中管理，缺失语言回退英文、缺失 key 回退 key 本身，为后续前端 i18n 建立统一文案通道。

- 笔记编辑器移除语言选择下拉框：统一使用 `everlingo.yaml` 配置的默认目标学习语言（`user_profile.language.target_language`）；未配置时阻止编辑并引导至设置页。

- MCP 新增 reset_vault 工具（仅重置 spec/*.md，不碰用户笔记数据），后端新增 POST /api/target-language/reset-vault 端点。
- vault MCP server 工具计数统一修正为 18 个（文档/注释/指令文本同步更新，顺带补全此前 list_tags 漏列的问题）。
- 前端新增统一 fetch 包装（apiFetch / apiFetchJson）：所有 API 请求收到 401 时自动跳转登录页，并统一结构化错误处理；新增 React ErrorBoundary 兜底渲染异常，避免白屏。
- Web 页面 HTML 外壳（/、/login、/editor、/console/*、/self-service*）加 `Cache-Control: no-store`，静态 hash 资源加 immutable 长缓存，manifest 加 no-cache，避免 iOS PWA/浏览器缓存旧前端。
- PWA manifest 改为动态语言协商（`Vary: Accept-Language`）：`web/public/manifest.webmanifest` 仅保留语言无关字段，`name`/`short_name`/`description` 由后端 `src/everlingo/i18n/pwa.py` 的 `PWA_MANIFEST_TEXT` 按 `Accept-Language`（ws_router）或 `interface_language` + `Accept-Language`（单用户部署）注入；9 个 HTML 入口的 `apple-mobile-web-app-title` 改为 `{{pwa_short_name}}` 占位符由服务端替换。

- Chrome Extension 引入 i18n 框架（react-i18next + i18next）：新增 `extension/src/i18n/`（bootstrap 从 `chrome.storage.local` 读取缓存语言初始化、detect 启发式兜底、非 React 上下文的 menu.ts 提供右键菜单文案）与 `extension/src/locales/{zh-CN,en}/`（复用 web 字典并新增 extension 独有的 options 字典）；sidecar 与 options 两个入口接入统一 bootstrap，约 40 处硬编码中文文案迁移到字典，语言非法时回退浏览器语言启发值。
- 后端 `POST /api/session` 返回新增 `interface_language` 字段（Gateway 暴露当前 resolved 界面语言）：Chrome Extension 首次创建会话时从后端取得并缓存到 `chrome.storage.local`（与 device_id 同生命周期），并同步更新右键菜单文案；ws_router 多用户拓扑经代理转发亦自动生效。
- Vault 初始化模板按界面语言拆分：`templates/default/` 分为 `en/` 与 `zh-CN/` 两套（英文为翻译版，文件路径树一致）；`create_vault` / `reset_vault` 新增可选 `interface_language` 参数（复用 `resolve_interface_language()` 解析语义，模板子包缺失回退 `en`），`session.configure` 自动创建缺失 vault 时透传。后端调用链（Memory Writer / Chat Agent / Vault Editor / 目标语言设置页）均传入当前 resolved 界面语言。
- 新增 `src/everlingo/i18n/vault.py`（`EVENT_FILE_PREAMBLE` 事件文件前置内容 zh-CN/en + `event_file_preamble(interface_language)` 取值函数）；Memory Writer 写 events 文件首次创建时按 `entry.interface_language` 选择前置内容。`why_want_to_save_memory` 由固定中文枚举（`WhySave` Literal）改为自由文本 `str`：`mem_entries.py` / `request_memory_extract.py` 去掉枚举约束，AI 按界面语言生成原因，`agent.py` prompt 与 `mem_entry_spec.md` en/zh 模板说明同步更新。

## Bugs fixing

- 修复 Chrome 扩展选词翻译时，上下文段落 `paragraph_text` 只截取段落开头、把所选单词切掉的问题：当段落超过 500 字时，改为以选词为中心截取，保证上下文段落始终包含所选单词（Chrome 扩展 `ChatWindow` 与笔记编辑器 `MilkdownEditor` 同步修复）。
- 修复 iOS 主屏 PWA 使用一段时间后打开白屏的问题：认证过期/服务端重启后，应用从后台恢复时不再静默失败，而是复检认证态并兜底跳转登录页或提示重新加载。
- 修复服务端重启后聊天会话失效的死循环：SSE 检测到会话过期时自动清除本地持久化的旧会话并重建新会话，无需手动刷新页面。
