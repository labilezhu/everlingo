# 🎉 EverLingo v0.1.1 release notes

## New Features

- Added a "Re-initialize" button to the target learning language settings page: users can reset the knowledge base specs (`spec/`) to the template initial state with one click, overriding user customizations.

## Enhancements

- `interface_language` changed from required to optional: when not configured, it is automatically inferred at runtime from the OS locale, falling back to English `en` when no match is found; the UI language and the target learning language are decoupled into two independent sets (currently available UI languages: `zh-CN`/`en`). The inferred value is not written to the config file; it will be explicitly chosen by the user during the first-run onboarding flow instead.
- Backend user-facing fallback messages internationalized: fallback replies such as AI errors / service unavailable are returned according to the UI language (Chinese/English), so English users no longer receive Chinese error messages.
- The Me page now shows the current EverLingo version number at the bottom, making it easy for users to identify the running version.
- First-run onboarding adds a new first step "Choose interface language": on first run users are forced to navigate to the interface language settings page, and the language is written to config and the next step started only after explicit confirmation; the Me page adds an "Interface Language" entry that can be switched at any time, taking effect immediately (no refresh needed), with the Agent rebuilt by the backend.
- The web frontend is fully internationalized: the copy in Chatbot, Note Editor, Web Console, Login/self-service/PAT pages is now driven by bilingual dictionaries and switches automatically with the UI language.
- Web Chatbot conversation state is now persisted: after switching between the chatbot and the note editor (full page refresh), the same conversation and message history are kept within the same browser tab, the AI context remains continuous, and nothing is cleared.
- Conversations are isolated per tab: opening a new tab creates an independent new conversation, enabling users to maintain multiple non-interfering conversations in the browser at the same time.
- The root-level `spec/` and `events/` directories in the file tree are collapsed by default to reduce visual clutter; users can expand them manually.
- PWA installation info (manifest's app name/short name/description and the iOS add-to-home-screen title) is negotiated dynamically based on request language: users with an English UI see the app name in English after installing the PWA, and Chinese users see Chinese.
- Chrome Extension (sidecar panel & settings page) UI copy internationalized: switches automatically according to the backend's resolved user interface language (`zh-CN`/`en`), and the right-click menu "Translate" label is localized accordingly.
- The initialization templates for creating a new language vault (`Vault`) are localized per UI language: the `spec/` specs and the `items/` and `events/` directory titles created by `create_vault` / `reset_vault` / `session.configure` are generated according to the user's UI language (Chinese/English), so English users no longer receive Chinese spec descriptions.
- The preamble content written when memory vault event files (`events/`) are first created is localized per UI language: the Chinese "当天事件" (today's events) title no longer appears in English UI; the "why remember" field `why_want_to_save_memory` is now freely written as a one-line reason by the AI according to the UI language (instead of a fixed Chinese enum).

## Bugs fixing

- Fixed an issue in the Chrome Extension word-translation feature where the context paragraph `paragraph_text` only captured the beginning of the paragraph and cut off the selected word: when the paragraph exceeds 500 characters, it now takes a snippet centered on the selected word, guaranteeing the context paragraph always includes the selected word (fixed in sync in the Chrome Extension's `ChatWindow` and the Note Editor's `MilkdownEditor`).
- Fixed a white-screen issue in the iOS home-screen PWA after prolonged use: when authentication expires / the server restarts, the app no longer fails silently on resume from background but re-checks the auth state and falls back to the login page or prompts a reload.
- Fixed an infinite loop where the chat conversation went stale after a server restart: when SSE detects the conversation has expired, the locally persisted stale conversation is automatically cleared and a new conversation rebuilt, without requiring a manual page refresh.


## Internal Changes

- Frontend introduced the i18n framework (react-i18next + i18next): added `web/src/i18n/` (multi-entry bootstrap: first renders the first screen heuristically by browser language, then corrects with the server-side `interface_language_resolved`, `/login` skips the status request to prevent a 401 infinite loop) and `web/src/locales/{zh-CN,en}/` nine dictionaries; all 9 Vite entries are wired into the unified bootstrap.
- Frontend introduced the vitest + @testing-library test stack: covers i18n dictionary consistency (zh/en keys deeply equal, placeholder consistency), bootstrap order, detect heuristics, and interface language page interaction, totaling 17 test cases.
- Added the `interface_language` fields (`interface_language` / `interface_language_resolved` / `available_interface_languages`) to `GET /api/user-profile/status` and the `POST /api/user-profile/interface-language` write endpoint (validation + yaml write + explicit `bump_prompt_version()` to trigger Agent rebuild), with fallback for the `/console/me/interface-language` static page.

- All LLM requests now uniformly carry app-identifying headers (`User-Agent: EverLingo/<version>`, `HTTP-Referer`, `X-Title`) so EverLingo traffic can be identified on platforms like OpenRouter; the version number is consolidated into `__version__` in `src/everlingo/__init__.py` and is auto-replaced as part of the release flow.

- Added `src/everlingo/i18n/` message dictionaries and the accessor `t(key, interface_language)`: backend fallback copy is centrally managed, missing languages fall back to English and missing keys fall back to the key itself, establishing a unified copy channel for the future frontend i18n.

- Removed the language selection dropdown from the Note Editor: it now uniformly uses the default target learning language configured in `everlingo.yaml` (`user_profile.language.target_language`); when not configured, editing is blocked and the user is guided to the settings page.

- MCP added the `reset_vault` tool (only resets `spec/*.md`, does not touch user note data); the backend added the `POST /api/target-language/reset-vault` endpoint.
- The vault MCP server tool count was uniformly corrected to 18 (docs/comments/instruction texts updated in sync, also fixing the previously missing `list_tags`).
- Frontend added a unified fetch wrapper (`apiFetch` / `apiFetchJson`): all API requests receiving 401 automatically redirect to the login page and use unified structured error handling; added a React ErrorBoundary fallback to render exceptions and prevent white screens.
- The Web page HTML shells (/, /login, /editor, /console/*, /self-service*) are served with `Cache-Control: no-store`, static hashed assets get immutable long caching, and the manifest gets no-cache, preventing iOS PWA/browsers from caching stale frontends.
- The PWA manifest now does dynamic language negotiation (`Vary: Accept-Language`): `web/public/manifest.webmanifest` keeps only language-agnostic fields, while `name`/`short_name`/`description` are injected by `PWA_MANIFEST_TEXT` in the backend's `src/everlingo/i18n/pwa.py` according to `Accept-Language` (ws_router) or `interface_language` + `Accept-Language` (single-user deployment); the `apple-mobile-web-app-title` of all 9 HTML entries is changed to a `{{pwa_short_name}}` placeholder substituted by the server.

- Chrome Extension introduced the i18n framework (react-i18next + i18next): added `extension/src/i18n/` (bootstrap reads the cached language from `chrome.storage.local` to initialize, detect heuristics as fallback, and `menu.ts` in non-React contexts provides the right-click menu copy) and `extension/src/locales/{zh-CN,en}/` (reuses the web dictionaries plus an extension-only options dictionary); both the sidecar and options entries are wired into the unified bootstrap, roughly 40 hardcoded Chinese strings migrated to dictionaries, and illegal language values fall back to the heuristic browser-language value.
- Backend `POST /api/session` response now includes the `interface_language` field (the Gateway exposes the current resolved UI language): the Chrome Extension fetches it from the backend when creating the session for the first time and caches it in `chrome.storage.local` (same lifecycle as `device_id`), and updates the right-click menu copy accordingly; it also takes effect automatically in the ws_router multi-user topology through the proxy.
- Vault initialization templates split per interface language: `templates/default/` is split into `en/` and `zh-CN/` sets (English is the translated version, with identical file path trees); `create_vault` / `reset_vault` gain an optional `interface_language` parameter (reusing the `resolve_interface_language()` resolution semantics, falling back to `en` when the template subpackage is missing), and `session.configure` passes it through when automatically creating a missing vault. The backend call chain (Memory Writer / Chat Agent / Vault Editor / target language settings page) all pass the currently resolved interface language.
- Added `src/everlingo/i18n/vault.py` (`EVENT_FILE_PREAMBLE` event file preamble content zh-CN/en + the `event_file_preamble(interface_language)` accessor); the Memory Writer selects the preamble content by `entry.interface_language` when an events file is first created. `why_want_to_save_memory` changed from a fixed Chinese enum (`WhySave` Literal) to free-text `str`: `mem_entries.py` / `request_memory_extract.py` drop the enum constraint, the AI generates the reason according to the interface language, and the `agent.py` prompt plus `mem_entry_spec.md` docs are updated in sync.
- Agent input/output contract specs migrated into code assets: `envelope_spec.md` / `mem_entry_spec.md` / `memory_extract_output_spec.md` moved from `vault/templates/{zh-CN,en}/spec/` to `src/everlingo/agents/spec/` (only zh-CN retained, as they are internal agent contracts no longer distinguished by interface language); Chat Agent and Memory Writer now compile and load them from a local `PackageSource` (no online vault dependency), and `memory_extract_output_spec` is directly injected into the Chat Agent system prompt, no longer requiring the LLM to load it via `vault_mcp_read` at runtime.
- Documentation internationalization: README split into the Chinese `README.zh-CN.md` and the English `README.md` (each with its own dedicated media directory); deployment docs are bilingual as `multiple-user-auth-deployment.md` (English) / `multiple-user-auth-deployment.zh-CN.md` (Chinese); the deployment script version number in the multi-user auth deployment doc was updated in sync.

- Default LLM model updated from `deepseek/deepseek-v4-flash` to `deepseek/deepseek-v4-flash-0731`: the sample configs in both the Chinese and English READMEs, `deploy/ws-container/ws-container-spec.md`, and `docs/impl-spec/multiple-users/ws-master.md` were updated in sync.
- README screenshots and images updated (new web chat / rounded-corner style images), and the `.agents/skills/round-corners-of-images` image rounding skill was added.
