# 界面国际化（i18n）设计

本文件是 EverLingo 界面国际化工作的整体路线图与各 Phase 详细方案。

## 范围

需要国际化支持的界面：

- [Web Chatbot](../impl-spec/web-chatbot.md) — Vite + React + shadcn/ui
- [Vault Editor](../impl-spec/vault-editor.md) — 同一 Vite 工程
- [Chrome Extension Sidecar](../impl-spec/chrome-extension-spec.md) — 独立 React 代码副本（`extension/src/components/`）
- [Chat Agent](../impl-spec/chat-agent-spec.md) — Python + langchain，给 LLM 的 system prompt + 少量用户可见兜底文案

## 可用界面语言

当前：`zh-CN`、`en`（两种）。

未来会扩展更多界面语言，并支持前端运行时切换 UI 语言。设计上需为此预留扩展点：

- `可用界面语言` 与 `可用目标学习语言`（`LANGUAGES` 字典 keys：en/ja/zh-CN/fr/de）是**两个独立集合**，语义不同，不可混用。
- 界面语言的「语言代码 → 显示名」映射**复用** `src/everlingo/models.py` 的 `LANGUAGES` 字典（单一真源），不为界面语言另建映射表。
- 可用界面语言以独立常量 `AVAILABLE_INTERFACE_LANGUAGES: tuple[str, ...]` 表达（保序，便于 UI 直接 iterate 展示），定义在 `src/everlingo/models.py`。
- 扩展可用界面语言时只需修改该常量 + 补齐对应 locale 字典，不需动 `LANGUAGES`。

## interface_language 配置语义

`everlingo.yaml` → `user_profile.language.interface_language`：

- **可选**（曾经是必选，本批改为可选）。
- 非空时**必须** ∈ `AVAILABLE_INTERFACE_LANGUAGES`，否则 `UserProfile.validate()` 报错。
- 留空时，运行时按以下顺序推断（`resolve_interface_language()`）：
  1. yaml 值非空且合法 → 直接用；
  2. `locale.getlocale()` 取 OS 语言，归一化（`lower`、`_`→`-`、去编码后缀）后精确命中可用集 → 返回；
  3. 前缀兜底：`zh-*` → `zh-CN`，`en-*` → `en`；
  4. 仍未命中 → `"en"`。
- **推断值不写回 yaml**。推断仅作运行时兜底；显式值由 onboarding（Phase 3）或 Me 页切换 UI（Phase 3）写入。
- 双访问器（避免推断值污染持久化配置）：
  - `load_profile()` — 返回 raw（interface_language 可能为空或非法），供 `save_profile` / onboarding status / `validate` / conf_manager 等使用。
  - `load_resolved_profile()` — 返回 raw 的副本，`interface_language` 经 `resolve_interface_language()` 填充为非空合法值，供运行时消费者（Agent / Gateway）使用。

## Phase 路线图

### Phase 1 — 配置层（当前）

**目标**：把 `interface_language` 从「必选」改为「可选 + OS locale 推断」，并建立「可用界面语言」独立集合的建模。仅后端/配置/文档层，不动前端、不动 onboarding 流程、不动 Chat Agent 兜底文案。

**决策记录**：[ADR 20260806-interface-language-optional.md](../ADR/20260806-interface-language-optional.md)

**改动清单**：

#### 源码（3 个文件）

1. `src/everlingo/models.py`
   - 新增 `AVAILABLE_INTERFACE_LANGUAGES: tuple[str, ...] = ("zh-CN", "en")`，注释说明 display 名复用 `LANGUAGES[code]`。
   - 新增 `resolve_interface_language(value: str) -> str`（4 步：精确命中 → OS locale 归一化精确命中 → 前缀兜底 zh-*/en-* → `"en"`）。
   - `UserLanguage.interface_language` description 改为「界面语言，可选；留空时按 OS locale 推断，兜底 en；非空时必须在可用界面语言内」。
   - `UserProfile.validate()`：删「界面语言未设置」；新增「`interface_language` 非空但 ∉ `AVAILABLE_INTERFACE_LANGUAGES`」→ 报「界面语言取值不被支持」。
   - `UserProfile.is_complete()`：去掉 `interface_language` 检查，仅 `target_language` 非空（与 onboarding status 端点语义一致）。

2. `src/everlingo/setting.py`
   - 新增 `load_resolved_profile() -> UserProfile`：调 `load_profile()` + `resolve_interface_language()`，返回 `model_copy`，不写回 yaml。
   - `load_profile()` 不动。

3. 运行时消费者（仅 2 处调用点改为 `load_resolved_profile()`）：
   - `src/everlingo/agents/agent.py` `_refresh_agent_if_needed()` 中 `profile = load_profile()` → `load_resolved_profile()`。
   - `src/everlingo/gateway/gateway.py` 中 `profile = load_profile()` → `load_resolved_profile()`。

#### 测试

`tests/test_setting.py` 扩展：

- yaml 合法值 → 直接用，不推断。
- yaml 空 + monkeypatch `locale.getlocale` 返回 `("zh_CN", "UTF-8")` → `zh-CN`。
- yaml 空 + `("en_US", None)` → `en`。
- yaml 空 + `(None, None)`（容器常见）→ `en`。
- yaml 非法 `fr` → `validate()` 报错；`load_resolved_profile()` 走推断容错。
- `is_complete()` 不再因 interface_language 空而返回 False。
- `load_resolved_profile()` 后调 `save_profile()` 不污染磁盘 yaml（前后 yaml 中 interface_language 仍空）。
- `AVAILABLE_INTERFACE_LANGUAGES` ⊆ `LANGUAGES.keys()` 一致性断言。

#### 文档与模板

- `DOMAIN.md` §语言：「可用界面语言」改为「当前：zh-CN、en（未来扩展）」；强调 interface 与 target 是两个独立集合、display 名查 `LANGUAGES`。
- `DOMAIN.md` UserProfile 表：`interface_language` 约束「必选」→「可选，留空时推断，非空时须在可用界面语言内」；删「均必须设置」中 interface 部分。
- `user-docs/reference/configuration.md`：同步上述措辞。
- `everlingo.example.yaml`：`interface_language` 注释改为可选 + 推断说明；示例值改空。
- 移除/注释默认 `interface_language: zh-CN` 的模板/文档：
  - `deploy/ws-container/ws-container-spec.md`
  - `deploy/ws-container/root/home/everlingo/.everlingo/workspaces/default/everlingo.yaml`
  - `docs/impl-spec/multiple-users/ws_container_everlingo_template.yaml`
  - `deploy/examples/ws_container_everlingo_template.yaml`
  - `README.md`
  - `user-docs/deployment/simple-single-deployment.md`

#### ADR

新增 `docs/ADR/20260806-interface-language-optional.md`。

#### 不在 Phase 1 范围

- onboarding step 1（界面语言选择页）→ Phase 3
- Me 页界面语言切换 UI → Phase 3
- `/api/user-profile/status` 暴露 `interface_language` → Phase 3
- Web 前端 i18n 框架（react-i18next 等）→ Phase 3
- Chat Agent 兜底文案 i18n → Phase 2（单独一期）

### Phase 2 — Chat Agent 兜底文案 i18n（单独一期）

**目标**：把 `src/everlingo/agents/agent.py` 与 `gateway/` 中给用户看的硬编码中文字符串集中到 `src/everlingo/i18n/messages.py`，按 `profile.language.interface_language` 取对应语言版本。

**边界**：

- **system prompt 本身不动**。`_build_system_prompt()` 的中文指令是给 LLM 看的，LLM 会根据 prompt 里的 `interface_lang` 字段自行决定回复语言，不需要国际化。
- 仅处理「用户可见的兜底文案」，例如：
  - 「当前通道不支持语音，请在微信等支持语音的通道使用。」
  - 「小记刚才断片了，对话忘记了，笔记还在」
  - 「出错了，请稍后重试」
  - 「AI 服务暂时不可用，请稍后重试 (已自动重试 2 次)」

**设计要点**：

- 新增 `src/everlingo/i18n/messages.py`：`MESSAGES: dict[str, dict[str, str]]` 按 `{lang: {key: text}}` 组织，`t(key, interface_language) -> str` 取值，缺失 lang 时回退 `en`，缺失 key 时回退 key 本身。
- 取值 lang 来源：`load_resolved_profile().language.interface_language`（Phase 1 已保证非空合法）。
- 不在 Phase 2 范围：前端文案 i18n（Phase 3）、system prompt i18n（不做）。

### Phase 3 — Web 前端 i18n 框架 + onboarding step 1 + Me 切换 UI

**目标**：引入前端 i18n 框架，把 Web Chatbot / Vault Editor / Me 页等界面的硬编码中文文案改为字典驱动；同时新增 onboarding 第一步「选界面语言」与 Me 页「界面语言」切换入口。

**设计要点**：

- **i18n 框架**：引入 `react-i18next`（轻量、生态成熟、支持 Suspense 懒加载 namespace）。目录：`web/src/locales/{zh-CN,en}/{common,chatbot,editor,me,...}.json`。
- **语言来源**：扩展 `GET /api/user-profile/status` 暴露 `interface_language`（raw + resolved）与 `available_interface_languages`（含 display 名，复用 `LANGUAGES`）。前端在 `main.tsx` 启动时拉取后 `i18n.changeLanguage(lang)`。
- **onboarding step 1**：首次启动引导流的第一步让用户选界面语言，选定后写入 yaml（此时 interface_language 非空，推断路径不再触发）。后续 onboarding 步骤（目标学习语言设置等）用所选界面语言展示。
  - 落点：新增 `/console/me/interface-language` 或并入现有引导流，具体由 Phase 3 设计时定。
  - 与 [ADR 20260801-user-onboarding.md](../ADR/20260801-user-onboarding.md) §9「interface_language 的可视化设置」衔接 —— 本 ADR 当时的「不引入」决定在 Phase 3 解除。
- **Me 页切换 UI**：Me 页新增「界面语言」设置入口，用户可切换 `interface_language` 并写回 yaml。
- **运行时切换**：前端 `i18n.changeLanguage()` 即时切换 UI 语言，不需刷新页面；切换并保存后后端 `bump_prompt_version()` 触发 Agent 重建。
- **PWA / shadcn 兼容**：react-i18next 与现有技术栈无冲突；两份 JSON 字典 ≈ 10~30KB，可接受。

**不在 Phase 3 范围**：

- Chrome Extension i18n → Phase 4
- Chat Agent 兜底文案（已在 Phase 2 处理）

---

### Phase 4 — Chrome Extension i18n

**目标**：Chrome Extension Sidecar 的 UI 文案国际化。

**设计要点**：

- Extension 是 web 组件的独立副本（见 [chrome-extension-spec.md §3 代码位置](../impl-spec/chrome-extension-spec.md)），按现有「独立维护」策略，**复制 `web/src/locales/` 到 `extension/src/locales/`**，同样引入 `react-i18next`。
- 语言来源：extension 启动时已有 `server_url`/`device_id` 等配置；新增 `interface_language` 到 `chrome.storage.local`（首次创建 session 时由后端返回并缓存），与 `device_id` 同生命周期。
- **不引入** `_locales/` + `chrome.i18n`（那是给扩展 UI manifest 用的，与 React 内文案体系不一致）。
